# Workflow de release
Tu release.yml ya tiene:
permissions: packages: write
GITHUB_TOKEN y CHANGESETS_GITHUB_TOKEN

No necesitas un PAT: el GITHUB_TOKEN del job funciona para publicar a GitHub Packages si tienes packages: write (ya lo tienes).

## Versionado y publicación

Ejecuta Changesets para reflejar el rename y disparar una release:
pnpm changeset (marca “minor” o “patch”; el rename de scope no es breaking para consumidores internos, pero en externos implica cambiar import, así que sugeriría minor).

## Commitea el changeset.
Haz push a main; el workflow abrirá el PR de “Version Packages” si corresponde, o publicará según tu configuración.

Verifica en la pestaña Packages de la nueva org que aparezcan @empresa/ui y @empresa/tokens.

En proyectos que consumen tus libs:

Validaciones rápidas

```
pnpm install en el monorepo tras los renames.
pnpm -w -C packages/tokens build
pnpm -w --filter @empresa/ui build
pnpm -w --filter docs build
```

Cuando el workflow publique, verifica que las tarballs y el dist contengan los cambios del scope.
